**Bottom line:**

  0.997× default Kitsune's input.

- **Coexistence unchanged:** Kitsune never moved the user's view (Playwright did in 26 of 28 runs). The typing user
  kept their input in 3/3 Kitsune runs and 0/3 Playwright runs (0 against 384 misdirected characters).
- **One regression since this morning's main `3a287f5`:** kitsune#457 now names removed elements in action results.

## Issue and improvement candidates

From this cohort, with `3a287f5` as a repeat where it applies. No new model calls were made. Severity is a judgement
of cost and frequency in these runs. Filed as kitsune#471–#475 and benchmark #120–#124.

### K1. Removal lines fill deltas when a region re-renders (medium; regression since `3a287f5`)

Filed as [kitsune#471](https://github.com/junyeong-nero/kitsune/issues/471).

- kitsune#457 counts a removed element as a change and names it, so closing a dialog no longer returns
  `no_visible_change`. `3a287f5` had 6 such results on `ui-modal` and `ui-autocomplete`; this cohort has none.
- The named element is the top one of each removed part whose parent line remains. When a region re-renders as a list
  of siblings, every old sibling is such a top element. The same clicks, in result characters (isolated / crowded):

  | Action | `3a287f5` | `286cfe5` | Removal lines |
  | --- | ---: | ---: | ---: |
  | `ui-table` page "2" | 1,339 / 1,350 | 2,182 / 2,198 | 28 |
  | `ui-table` page "3" | 786 / 793 | 1,625 / 1,640 | 28 |
  | `ui-table` page "1" | 1,336 / 1,347 | 2,035 / 2,053 | 23 |
  | `ui-datepicker` "›" (next month) | 1,780 / 1,815 | 3,031 / 3,091, `snapshot_truncated` | 24, then cut |
  | `ui-datepicker` day pick (calendar closes) | 146 / 147 | 1,667 / 1,703 | 34 |

- Kitsune input on those units, `3a287f5` → `286cfe5`, one run each:
  - `ui-table` isolated 88,283 → 110,851 (+26%, with one more page click), K/PW 1.04 → 1.28;
  - `ui-table` crowded 160,160 → 188,260 (+18%, with one more scoped snapshot), K/PW 0.45 → 1.48. Playwright's own
    input fell from 359,552 to 126,994;
  - `ui-datepicker` isolated 54,693 → 61,065 (+12%), crowded unchanged.
- In the cohort, 438 removal lines (14,750 characters) appear in 44 action results of 24 Kitsune runs: 16 gallery and
  8 external. The removals #457 aimed at stay useful, for example `- removed: button "음악 태그 삭제"` (`ui-tags`) and
  `- removed: button "START"` (`mw-book-flight`).
- **Proposal:** fold removals that share a parent, as #458 folds similar siblings. Beyond a few lines, name the first
  removal and count the rest, for example
  `- removed: button "2027년 6월 1일" [ref=e9] … and 29 more under main [ref=e2]`. Keep single removals as they are.
- **Acceptance:** a `ui-table` page click and a `ui-datepicker` month switch each carry a few removal lines, and the
  "저장" click on `ui-modal` still names the closed dialog.

### K2. A write sent with the copy's navigation uses the user tab's refs (medium; after kitsune#459)

Filed as [kitsune#472](https://github.com/junyeong-nero/kitsune/issues/472).

To write in a page it read in a user's tab, the agent opens its own tab with the same URL. In 3 runs it sent that
navigation and the write in one request, using refs from the user tab's snapshot. Kitsune issues new refs for each
document, so the write failed with `stale_ref` (`other_document`):

| Run | Failed request | Retry | Requests K / PW | K/PW input |
| --- | --- | --- | --- | ---: |
| `pb-research-01` personal v1 | `navigate` + `type e6` + `click e7` + `snapshot` | `type e15` + `click e16` + `snapshot` | 6 / 5 | 1.24 |
| `pb-research-01` coexistence | `tabs new` + `type e6` | `type e15` + `click e16` + `snapshot` | 6 / 5 | 1.24 |
| `pb-handoff-04` personal v1 | `navigate` + `type e4` | `type e14` + `click e15` | 7 / 6 | 1.20 |

- #459 named the same element in all 4 errors, and each retry used that ref without a new snapshot. The failed
  request still costs one more request per run. Each of these runs used 13–14k more input tokens than Playwright's,
  about one request's worth, and they are 3 of the 9 units above 1.10.
- On `3a287f5`, before #459, the same pattern hit 3 runs. Nothing was written in the wrong place.
- **Proposal:** warn before the batch, keeping #459's rule that Kitsune does not write to the matched element itself.
  The read-only hints in `tabs list` and `select` already say "To write, open your own tab with browser_tabs
  action=new url=…". They could add that the new tab gets new refs, and that refs from this tab do not apply there.
  Measure the change in an A/B on `pb-research-01` and `pb-handoff-04`.

### K3. Reading another tab with `target: "tab:1"` (low)

Filed as [kitsune#473](https://github.com/junyeong-nero/kitsune/issues/473).

- `browser_snapshot {target: "tab:1"}` returned `unsupported_selector` in 2 runs (`pb-safe-02` coexistence,
  `pb-handoff-01` v1). On `3a287f5` it happened in `pb-safe-02` coexistence. Each time the agent wanted another tab's
  page without switching to it. Each call went out with others, so it cost no request.
- Since #449 any tab can be read, but the core reads take no tab argument, and the hint lists only selector forms.
- **Proposal:** when a target looks like a tab (`tab:N`, `tab=N`), the hint says to call `browser_tabs action=select
  index=N` and then `browser_snapshot`, and that `select` does not change the user's view.

### K4. The `other_document` hint names `tab_id`, which core tools do not publish (low)

Filed as [kitsune#474](https://github.com/junyeong-nero/kitsune/issues/474).

- The hint reads "Take a new browser_snapshot of the intended tab (select it with browser_tabs, or pass tab_id)". This
  is `shortRefError` in `background.js`; `content.js` has "Pass tab_id and take a new browser_snapshot."
- Core `browser_snapshot`, `browser_type` and `browser_click` publish no `tab_id` (`playwright_tools.json`) and do not
  take one.
- **Proposal:** under core, name only `browser_tabs` `select`. #448 fixed the `no_current_tab` hints the same way
  (`b4322bd`).

### K5. Key presses still settle for about 0.5 s (low)

Filed as [kitsune#475](https://github.com/junyeong-nero/kitsune/issues/475).

- #460 halved the field writes (table above). `browser_press_key` stays at a p50 of 0.48 s on both mains, against
  Playwright's 0.02 s, over 25 calls in 5 gallery runs.
- #460 kept the floor for keys on purpose, because a key's reaction is often debounced. Here 20 of the 25 presses had
  already changed the page: arrow keys on `ui-slider` and `ui-sortable` with `prevented: true`, and an Enter on
  `ui-editor`. Kitsune's runs are faster overall, so this is low.
- **Proposal:** end a key's settle early when the page handled the key (`prevented: true`), the settle watch saw
  mutations, and the page has since been quiet for `SETTLE_QUIET_MS`. Debounced reactions and keys with no visible
  change keep the floor.

### B1. Setup failures lose their cause (medium)

Filed as [#120](https://github.com/junyeong-nero/kitsune-benchmark/issues/120).

- `personal_session.main()` catches setup errors and records only `native_session_setup_or_inventory_failed`. The
  coexistence relay records `coexistence_session_setup_or_inventory_failed` in the same way.
- For the stop above, the user channel's `UserDriver` error was dropped, for example "Timed out waiting for the
  user's new tab." The driver made 132 calls in 7.4 s of driver time, which fits one 15 s `wait` running out, but the
  evidence cannot say which step failed. Earlier personal setup failures in `artifacts/personal/` carry the same single
  code.
- **Proposal:** write the exception text and its cause (`error_detail`) to the session evidence and the run summary.

### B2. One setup failure before the model starts costs a resumed entry (medium)

Filed as [#121](https://github.com/junyeong-nero/kitsune-benchmark/issues/121).

- `unscorable_pair` stops the suite for any setup failure, including one that ended before the model saw the task
  (`model_request_observed: false`).
- Resuming `--from personal-v1` reran the whole entry. 44 completed agent runs of the first run (28 Playwright, 16
  Kitsune) were spent again, which took about 16 minutes.
- **Proposal:** an opt-in `--retry-setup-failures N`. It reruns in place a pair whose run is `setup_failed` with no
  model request, and records each retry in the suite log. The model never saw the task, so a retry cannot select on
  outcomes. The running guide states "No automatic retry", so this is the owner's call.

### B3. The MDN advisory pattern misses a correct answer (low)

Filed as [#122](https://github.com/junyeong-nero/kitsune-benchmark/issues/122).

- Kitsune's final text says "Firefox (desktop) first supported it in **version 90**". The pattern
  `firefox\D{0,40}\b90\b|\b90\b\D{0,40}firefox` allows 40 characters between the two words; this answer has 43.
- The same wording missed twice on main `514b5b7` (both targets). Every MDN answer in `artifacts/` that fails the
  pattern is correct, and matches with a window of 80.
- The match is advisory, not a success label, but the summary reports Kitsune 1/2 against Playwright 2/2.
- **Proposal:** `tasks/external/catalog.json` is frozen. Widen the pattern in the next taskset tag, for example
  `\D{0,80}`. Until then, read the live answers by hand.

### B4. Gallery pages changed after `taskset-v3.4` (low; bookkeeping)

Filed as [#123](https://github.com/junyeong-nero/kitsune-benchmark/issues/123).

- #114 and #115 changed frozen files (`gallery_static/gallery.js`, `gallery.py`) after the tag, and #114 notes that
  the change belongs in a new taskset tag.
- This cohort's `ui-autocomplete` and `ui-modal` therefore differ from `taskset-v3.4`, from the v0.7.2 cohort and from
  `3a287f5`'s. The `ui-modal` isolated drop from 1.62 to 0.97 comes from both #115 and kitsune#457.
- **Proposal:** tag `taskset-v3.5` at `6159847` or at the next freeze, and record it under
  [Frozen taskset](kitsune-versions.md#frozen-taskset).

### B5. `analyze-release.py` counts batched calls as waste signals (low)

Filed as [#124](https://github.com/junyeong-nero/kitsune-benchmark/issues/124).

- All 155 `unchanged_since` snapshots were sent in the same request as the call they refer to, so none cost a
  request. Split by request, Kitsune's personal bare snapshots after a navigating call are 76 in the same request and
  0 in the next; Playwright's are 16 and 7.
- In personal, the "bare snapshots right after navigating" column counts 25 of them (after navigating clicks) and
  misses the 51 after `tabs new`. "Observation right after an action" also counts calls sent in parallel with the
  action.
- **Proposal:** count per model request, as `analyze-model-rounds.py` does. Separate observations sent after the
  action's result from those sent with it, and count `tabs new {url}` as navigating.
