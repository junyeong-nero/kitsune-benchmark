# WebArena-Pro: Kitsune v0.8.2 on Claude Code (API key)

**23 November 2026 · 26 attempts · Kitsune arm only · one repeat per cell.** Kitsune v0.8.2 passed 12/26 (test 6/19, dev 6/7) on the `claude-api` harness. The [20 November run](2026-11-20-webarena-pro-four-way.md) (Kitsune `4e6d6fb`, `claude` subscription) passed 13/26. Only `wap-077` changed, and total input and calls were within 1–2% of that run. **No material change from v0.8.2.** The README figure was not updated.

[Public per-attempt metrics (CSV)](2026-11-23-kitsune-0.8.2-claude-api.csv) · [Running guide](../running.md). Recompute with `python3 summary.py docs/results/2026-11-23-kitsune-0.8.2-claude-api.csv`. The CSV omits prompts, answers, tool payloads, credentials and transcripts.

Input includes cache reads and cache creation. Both runs report usage on 25/26 attempts; the `wap-247` timeout reports none.

- **Pass set:** the same 12 tasks passed in both runs. `wap-077` went from pass to fail: the agent answered with the first Delta flight in the site's "Best departing flights" section, not the expected `DL6387`. This was a reading of the task, not a tool failure.
- **`wap-247`** timed out at 600 seconds again. The agent read about 135 cities page by page; one script timed out at 120 seconds with nothing printed, and the rest ran in chunks under the 100-call limit ([Kitsune #618](https://github.com/junyeong-nero/kitsune/issues/618)).
- **`wap-341`** failed in both runs. In this run the cause was a Kitsune bug, not a reading of the task: `tab.text()` returned only the first `<article>` of a listing page, so 9 of 24 listings were read without a price, among them the cheapest Toronto one. The agent answered Montreal ($207) instead of Toronto ($206.54) ([Kitsune #613](https://github.com/junyeong-nero/kitsune/issues/613)).
- **Common-pass input +35%:** two tasks account for almost all of it. `wap-144` (90k → 340k, 3 tool errors) and `wap-233` (142k → 336k, 2 tool errors) recovered from `stale_ref` and `script_operation_limit` errors ([Kitsune #616](https://github.com/junyeong-nero/kitsune/issues/616), [#618](https://github.com/junyeong-nero/kitsune/issues/618)). Without these two, the other 10 used 778k vs 848k.
- **Tool errors 27 → 15, no navigation timeouts:** in the earlier run, three tasks hit the navigation timeout ([Kitsune #561](https://github.com/junyeong-nero/kitsune/issues/561)). This run had none. The remaining errors were:
  - `stale_ref` 4
  - `script_operation_limit` (100 operations) 3
  - `not_found` 2
  - `script_error` 2
  - `ambiguous_target` 1
  - other 3
- Cost: Claude Code estimated $5.20 for the run. The Anthropic Console is the billing source.

## Protocol and exclusions

- Command: `python3 benchmark.py --execute --harness claude-api --arm kitsune --allow-api-billing`, the 26 cells in matrix order. Every `api_key_source` was `ANTHROPIC_API_KEY`.
- Runner `b2ca5c2` plus the working-tree `claude-api` harness changes. Kitsune `v0.8.2` (`9a777eb`) ran in a separate runtime checkout with isolated headless Firefox. Model: `claude-opus-5-5`.
- Sites and Core: WebArena-Pro `42f4a076` in a Codespace, with container egress blocked. Ports went through `gh codespace ports forward`, which [can drop requests under parallel load](../running.md#4-connect-the-agent-host-to-the-sites) (kitsune#605); the 20 November run used the same forwarder. No tool error in this run was a request timeout. Each attempt recreated its sites and signed in before measurement.
- Grading is the same as on 20 November: `backend_state`/`answer_match`, and no working LLM judge. A rubric that escalates to `llm_judge` fails with `configuration_error`, as intended.
- Excluded: one earlier invocation that stopped on its first cell with `Invalid API key`. It made no model calls and reported zero usage. Raw evidence remains private.
