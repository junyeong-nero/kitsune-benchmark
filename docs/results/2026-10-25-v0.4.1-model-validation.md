### Editing: a silent no-op, not dropped modifiers

Kitsune's three deletion attempts performed **24 recorded key actions** across
fresh pages, with **zero changes to text/caret/selection**. This includes six
Backspace calls from the end of the nonempty field. Some other calls, such as
End while already at the end, are negative controls and must not all be counted
as independent failed primitives. There were **no MCP tool errors** in these
three runs. The models correctly reported inability and did not save a false
success or replace the whole field.

All three models additionally inferred that Shift/Meta had been dropped because
the tool reply echoed only the base key. **That inference is wrong**: page
telemetry records Shift and Meta on the corresponding six modified events.
The failure is the missing default editing behavior, not evidence of lost
modifiers. A useful response-contract improvement is to echo the full normalized
combination and distinguish event dispatch from supported/effective editing.

Kitsune's two successful newline runs used `browser_type` with
`text="\nBeta", slowly=true`. That is a working alternative insertion path,
**not evidence that Enter works**. The failed newline run also encountered the
invalid `mode="editable"` recovery guidance covered by #255.

**Diagnostic limitations, disclosed rather than retried:**

1. The page records saved state server-side, but a subsequent GET renders the
   original `Alpha` rather than reloading the saved value. One successful K
   model noticed this, repeated the insertion/save and incurred extra work.
   This is an experimental fixture limitation, **not a Kitsune persistence
   bug**. We do **not** attribute the editor's extra calls/tokens entirely to
   Kitsune or use their ratio as a product-efficiency claim. The saved-state
   goal outcome and independent key no-op proof remain distinguishable.
2. Page telemetry stores the latest page lifetime; reload resets its key list.
   A final empty key list is not proof that the model made no prior key attempts.
   Deletion runs did not reload, so their 24-event state comparison is intact.
3. The initial contenteditable text is absent from both tools' first snapshots
   in these fixtures. Later DOM shapes differ depending on how the newline was
   inserted. This is insufficient evidence for a new Kitsune-only snapshot bug.
4. The failed editor used a non-`slowly` type attempt, rejected as `not_fillable`.
   The grader records that prohibited whole-value-path **attempt**, not proof
   that the content was actually overwritten. Its goal also independently
   failed because no correct value was saved.

The clean deletion diagnosis and original nine-action no-model control should
be the primary evidence in A1, not the confounded editor cost totals.

## Table repetitions: observed overhead, bounded claim

Input below includes cache-read/write input, as reported by the harness. Calls
are **agent-visible MCP calls**, excluding hidden setup/grading RPCs. Requests
are deduplicated model requests, not MCP requests. Totals compare the same four
successful pairs per row; all attempts in these cells succeeded.

| Layout | Input PW / K | K input change | Calls PW / K | Model requests PW / K | K input higher |
| --- | ---: | ---: | ---: | ---: | ---: |
| Crowded | 1,165,768 / 1,217,095 | **+4.4%** | 68 / 62 | 41 / 50 | 2/4 pairs |
| Isolated | 358,410 / 456,430 | **+27.3%** | 60 / 53 | 25 / 36 | 3/4 pairs |

| Layout | Paired K/PW input ratios, repeats 0–3 | Median pair ratio | Pair range |
| --- | --- | ---: | ---: |
| Crowded | 0.955, 1.632, 0.745, 1.105 | **1.030** | 0.745–1.632 |
| Isolated | 1.247, 1.377, 0.988, 1.494 | **1.312** | 0.988–1.494 |

Crowded PW recovered from stale-ref / selector-mismatch errors in **3/4** runs,
while K had none. The crowded repeats therefore include varying recovery work,
not only identical action paths. Isolated table runs had no tool errors in
either target, and K used more model requests in all four pairs despite fewer
MCP calls. That is stronger evidence for studying round structure in the
isolated task, but it is still not an optimization A/B or proof of a mechanism.

The earlier crowded **+52.7%** and isolated **+39.4%** observations were across
three different variants. The new fixed-variant result does not reproduce a
stable crowded +53% penalty. Do not pool the cohorts or dismiss the variance.

**Next experiment, not yet run:** inspect which state changes require a new
model round and whether action results carry sufficient observations; compare
an explicit observation-reuse intervention against baseline with the same
success/safety contract. Do not blindly parallelize stateful edits or truncate
already smaller snapshots in an attempt to reduce request count.

## Slider: what the new evidence does and does not show

Kitsune's three runs each issued a text fill against `div[role=slider]`, received
`not_fillable` with this guidance, then recovered and completed the task:

> For a contenteditable editor use mode="editable".

The target is a slider, not an editor, and the exposed core tool schema has no
`mode` parameter. The hint is incorrect for both the target and the tool
contract. Playwright also rejects attempted text fills in two of its three
runs. Consequently, the issue is **misleading recovery advice**, not proof
that rejecting slider text-fill is itself wrong. Attach this evidence to #255.
