## Issue and improvement candidates

From this cohort, with `286cfe5` and earlier artifacts as repeats where they apply. No new model calls were made.
Severity is a judgement of cost and frequency in these runs. Filed as kitsune#483–#488 and benchmark #136–#140.

### K1. A one-option list is listed as a second button, and clicking it does nothing (medium)

Filed as [kitsune#483](https://github.com/junyeong-nero/kitsune/issues/483).

- `mw-book-flight` (MiniWoB++, jQuery UI autocomplete). After `browser_type` "Wenatchee" (slowly), the delta reads:

  ```
  - textbox "To:" [ref=e2] [value="Wenatchee"]
  - button "Wenatchee, WA (EAT)" [ref=e9]
    - button "Wenatchee, WA (EAT)" [ref=e10]
  ```

  e9 is the menu's `<ul>` and e10 its only option. With two options (the "From" field), the list shows two flat
  buttons.
- Clicking e9 returns `{"ok":true,"tag":"ul",…}` without a warning, and "To" keeps "Wenatchee".
  - In this cohort the agent noticed on its next snapshot and redid the choice with ArrowDown and a click: 2 more
    requests, input 108,881 → 146,506, K/PW 0.90 → 1.07.
  - The agent clicked the outer ref first in 3 of the 10 Kitsune `mw-book-flight` runs in `artifacts/external/`
    (all `claude-opus-5-5`, Kitsune `9f84b25` to `ad04bac`).
- **Cause:** the jQuery UI menu's `<ul>` has `tabindex` and no role, so `isControl()` makes it a control.
  `measure()` in `content.js` treats a generic control as a delegation wrapper only when it has a native descendant
  or at least two custom controls (`data.native > 0 || data.interactive >= 2`). With one option it is listed as its
  own button, named after that option. jQuery UI handles the click on the `<ul>` for its `.ui-menu-item` children,
  so a click dispatched to the `<ul>` itself selects nothing. Playwright clicks the point, which lands on the option.
- **Proposal:** treat such an element as a wrapper too when its single interactive descendant has the same name, so
  the snapshot lists only the option. A click on a wrapper could also go to the element at its centre, as a pointer
  does.
- **Acceptance:** the delta after typing "Wenatchee" lists one option. A no-model fixture with a one-item delegated
  menu lists one button, and clicking it selects the item.

### K2. Line breaks typed into a single-line field are deleted, not turned into spaces (medium)

Filed as [kitsune#484](https://github.com/junyeong-nero/kitsune/issues/484).

- In `pb-handoff-04` both agents type a multi-line reply into the draft field "답장", an `<input>`. The saved drafts:
  - Kitsune: "…안내드립니다.장소: 본관 3층 세미나실시작: 2027-06-24 (목) 10:00공식 안내 링크: …";
  - Playwright: "…안내드립니다. - 장소: 본관 3층 세미나실 - 시작 시각: …".
- **Cause:** `typeText()` in `content.js` writes through the native `value` setter, whose sanitization deletes line
  breaks in a single-line input. Playwright's fill goes through the editor (`insertText`), and Firefox then replaces
  each line break with a space, as it does when a user pastes (`editor.singleLine.pasteNewlines` = 2).
- Kitsune's result shows the run-together value. In all 6 Kitsune runs of this task over two cohorts (personal v0,
  v1, coexistence) the agent then wrote the reply again on one line, with " / " separators or as sentences, and saved
  again. Playwright did so in 0 of 6.
- **Cost:** one or two requests per run. These are 3 of this cohort's 17 units above 1.10: Kitsune made 8 requests in
  each, against Playwright's 6 (v0, v1) and 5 (coexistence).
- The grader passes either text. A task that needs a word boundary after the break could fail, for example
  "세미나실시작".
- **Proposal:** in a single-line `<input>`, replace each line break with a space before setting the value, as
  Playwright and Firefox do, and keep `<textarea>` and editors as they are.
- **Acceptance:** typing "a\nb" into an `<input>` stores "a b" on both servers (no-model test), and `pb-handoff-04`
  saves its reply once.

### K3. A collapsed run of a few rows costs a request when the task needs them (low)

Filed as [kitsune#485](https://github.com/junyeong-nero/kitsune/issues/485).

- `ui-table` isolated: the first snapshot is 1,250 characters. It lists 5 of the page's 8 rows, then
  `- … 3 more similar items; snapshot e13 to list all`. A target row, 마이크 (stock 3), is among the hidden ones, so
  the agent's second request is `browser_snapshot {target: "e13"}` (1,166 characters).
- Over two cohorts, every `ui-table` run expanded its collapsed rows (4/4, both layouts), and `mm-grid` did so in 3 of
  4 (4 hidden). Each expansion was a request of its own.
- In this cohort 79 of the 101 markers hide 3–5 items. Most sit in the crowded page's first snapshot, where the task
  does not need them, and the 3 expansions were the only ones.
- **Trade-off:** H18 ([2026-10-28](2026-10-28-h18-collapse-ab.md)) listed runs of up to 5 in full and was
  inconclusive. It removed `ui-table`'s expansions, but its guard units cost more.
- **Proposal:** collapse by size rather than by count, for example only when the hidden lines exceed about 600–1,000
  characters, or when the snapshot would otherwise exceed its budget. On the isolated page, 3 rows are about 440
  characters, and the request that fetches them costs about 10k input tokens.
- **Acceptance:** an A/B on `ui-table` and `mm-grid`, with H18's guards (`ui-infinite`, `pb-longpage-01`).

- The other 3 Kitsune `ui-infinite` runs of the two cohorts used `load_more` after the same hint.
- The first hover returned `no_visible_change: true`, yet a `find` 0.2 s later already saw its 10 new items. The page
  loads 400 ms after the sentinel becomes visible, and that hover's settle ended at 0.54 s. This is the async-delta
  limit noted for v0.7.1. The next six hovers caught their loads.
- **Proposal:** when an action's delta adds similar items at the end of a list that has a loading sentinel, add a
  hint that `browser_find text=… load_more=true` scrolls until a match appears.
- **Acceptance:** measure on `ui-infinite` in both layouts. One run of four is not an effect, so this is low.

### K5. The tab-target error keeps the generic selector hint (low)

Filed as [kitsune#487](https://github.com/junyeong-nero/kitsune/issues/487).

- The `error` text explains `tab:1` (#473). The `hint` field still lists every selector form Kitsune resolves
  (about 380 characters), which does not apply to a tab.
- Neither agent selected the tab (above).
- **Proposal:** for a tab target, make the hint the select-then-snapshot step and drop the selector list.

### K6. `tabs new` and `select` results repeat the whole tab list (low)

Filed as [kitsune#488](https://github.com/junyeong-nero/kitsune/issues/488).

- Kitsune's tab results:

  | Action | Calls | Mean characters | Playwright calls | Playwright mean |
  | --- | ---: | ---: | ---: | ---: |
  | `list` | 123 | 506 | 67 | 290 |
  | `new` | 127 | 851 | 36 | 990 |
  | `select` | 83 | 622 | 119 | 408 |

- The `tabs` arrays are 69% of Kitsune's tab-result characters (152k of 222k). The read-only hints are 12%.
- Early tab results are carried in every later request. In personal v0, Kitsune's `browser_tabs` results have the
  largest carried size of any tool: 183k characters, against snapshots' 95k (Playwright's tabs: 118k).
- At most about 1% of Kitsune's input.
- **Proposal:** in `new` and `select` results, list only the tab acted on and the tab count, or omit the list when it
  is unchanged since the last list result that client saw. `action=list` stays as it is.
- **Acceptance:** an A/B on personal tasks with several starting tabs.

### B1. The native coexistence Kitsune tests fail since kitsune#448 (medium)

Filed as [#136](https://github.com/junyeong-nero/kitsune-benchmark/issues/136).

- `test_user_seeded_tabs_are_user_owned_and_view_stays` and `test_typing_user_is_not_disturbed`
  (`tests/test_coexistence.py`, `NativeKitsuneCoexistenceTests`) fail on `286cfe5` and `ad04bac`. They pass on v0.7.2
  and `3a287f5`. The failure is "No textbox '메모' in snapshot: unchanged since the browser_tabs result (refs e1–e8)".
- Since #448, a core `tabs new` result carries a small page's snapshot. The next whole-page `browser_snapshot` then
  answers `unchanged_since`, so the scripted agent finds no ref.
- These are the only no-model checks of the coexistence relay against a real Kitsune, and the `286cfe5` cohort ran
  without them.
- **Proposal:** take refs from the `tabs new` result's snapshot, as model runs do, or take a snapshot only when that
  result carries none. Then run the native tests as part of every cohort's preflight.

### B2. The native viewport check cannot run on Kitsune v0.7.2 and later (medium)

Filed as [#137](https://github.com/junyeong-nero/kitsune-benchmark/issues/137).

- `test_taskset_v3.py` `NativeKitsuneViewportTests` errors 3 times on v0.7.2, `286cfe5` and `ad04bac`, and passes on
  v0.7.1 and `514b5b7`.
- The check seeds by navigating the fresh profile's tab. That tab is the user's, so Kitsune refuses: `no_current_tab`,
  and `user_tab_read_only` once the tab is selected.
- The running guide says to rerun this check after a Firefox or Kitsune upgrade. Each personal run's beacon still
  asserts its viewport (112/112 here), so this cohort's viewport claim stands. What goes unchecked is the window
  construction (1280×805) on a new Kitsune.
- **Proposal:** seed it as #95 did for the native personal test: the user channel opens the pages, and the agent
  reads in its own tab. While there, update the running guide's test counts ("65 tests", "69 tests"; now 410 with 18
  skipped).

### B3. The release review does not say which target moved (low–medium)

Filed as [#138](https://github.com/junyeong-nero/kitsune-benchmark/issues/138).

- `analyze-release.py --compare` gives Kitsune/Playwright ratios then and now, but not each target's own input or
  requests on the units both solved in both suites.
- In this cohort, personal and isolated moved on Playwright's side. 4 of the 17 units above 1.10 are there because
  Playwright got cheaper, for example `ui-editor` crowded, where Playwright's input fell from 375k to 117k. The
  `286cfe5` report built this table by hand, and so did this one.
- **Proposal:** add a per-group table of each target's input and requests then → now on those units, and mark each
  unit above the outlier ratio with the side that changed.

### B4. `analyze-per-tool.py` labels coexistence and external failures `miniwob` (low)

### B5. `analyze-per-tool.py` pools latency across tracks (low)

Filed as [#140](https://github.com/junyeong-nero/kitsune-benchmark/issues/140).

- The pooled median follows the mix of tracks. Kitsune's moved from 0.26 to 0.34 s while no track's p50 moved by more
  than 0.02 s.
- **Proposal:** report p50/p90 per group, as the release review does for cost, and per action for `browser_tabs`.

## Limits

- One attempt. Kitsune and Playwright ran concurrently in personal, gallery and external, so elapsed times are under
  shared load.
- `286cfe5` is the only baseline. Its MDN advisory pattern is the 40-character one; everything graded is the same.
  Kitsune personal results compare only with `taskset-v3.2` and later cohorts, `pb-tabs-03` only from `taskset-v3.3`,
  the coexistence arm only from `taskset-v3.4`, and `ui-autocomplete` and `ui-modal` only with cohorts on
  `taskset-v3.5`'s pages, `286cfe5`'s included.
- The live tasks are ungraded. No hostile-UI matrix and no full-native track ran. The native coexistence and viewport
  checks could not run (B1, B2).
- #481 was not exercised. No prompt came up, so the decline policy was never applied.
