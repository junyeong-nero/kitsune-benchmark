# H321: truncated snapshots list no link URLs, on live sites — frozen protocol

[Results index](../results/README.md) · [kitsune#321](https://github.com/junyeong-nero/kitsune/issues/321) ·
[H310 report](../results/2026-10-28-h310-snapshot-budget-ab.md)

This file freezes the cohort before any agent run. It was committed before the first execution and is not edited
after that. Results go in a separate report.

**H321:** Kitsune main with #319 keeps `main` within the snapshot budget on pages with large navigation. On real
pages, though, the links inside `main` have distinct URLs, and their `/url` lines still take 14–48% of the snapshot.
Listing no link URLs in a snapshot that is cut for budget (without a target) keeps more of `main` in the first
snapshot. It should lower total input on live-site tasks without lowering completion or answer quality. Pages that fit
the budget are unaffected.

## Arms

| Arm | Kitsune checkout |
| --- | --- |
| A, baseline | `main` `5dbcaff` (includes #319: landmark deferral, same-origin paths, repeated URLs left out), clean detached worktree |
| B, intervention | `exp/drop-urls-when-truncated` `9608032` = `5dbcaff` + one commit. A snapshot cut for budget without a target lists no `/url` lines, and its deferred-landmark markers do not count them. It returns `urls_omitted: true`, and the core hint adds one sentence. Whole, targeted, delta and `filename` snapshots and `browser_find` are unchanged |

Tool names, descriptions and schemas are identical. On B, Kitsune's suites pass: every `tests/*.cjs`, 890 Python
tests, and the real-browser snapshot suites. The full real-browser suite fails 13 tests on B, all of which also
fail on A (A fails 15).

## Stops

The driver stops (exit 2) on any of these:

- a harness error without a summary;
- two unscorable (incomplete) runs in a row;
- a Kitsune revision change or dirty checkout;
- different tool surfaces between the arms;
- a truncated snapshot on B that still lists `/url` lines (the change is not in effect).

## Estimands and decision (predeclared)

A pair is a cell repeat where both arms completed.

- **Primary estimand:** the live input ratio, Σ input tokens(B) / Σ input tokens(A) over joint pairs.
- **Secondary** (reported, not decisive):
  - the median per-pair request ratio;
  - `browser_find` calls, truncated snapshots, MCP calls;
  - elapsed time;
  - per-cell ratios.
- **Guard estimand:** the pooled guard input ratio.
- **Gates**, per cell:
  - B's completions ≥ A's;
  - B's advisory matches ≥ A's;
  - B's safety failures ≤ A's (gallery guards).

| Verdict | Condition |
| --- | --- |
| **support** | ≥ 10 joint primary pairs, live input ratio ≤ 0.90, pooled guard ratio ≤ 1.05, every gate holds |
| **reject** | ≥ 10 joint primary pairs and live input ratio ≥ 1.00 |
| **inconclusive** | anything else |

Live sites change during the cohort, and model paths vary more on them than on fixtures. The arms are interleaved
per repeat, so a site change hits both arms. A result is about these three pages on this date. It is not a general
claim.
